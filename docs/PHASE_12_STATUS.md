# Phase 12 — Finance Foundation

## هدف

ایجاد هسته واقعی ماژول مالی نوژین روی معماری Local-first موجود.

## محدوده این فاز

- حساب‌های مالی
- نوع حساب: نقدی، بانکی، کیف پول، پس‌انداز، سایر
- ارز پیش‌فرض تومان
- موجودی اولیه
- درآمد و هزینه
- ثبت و حذف تراکنش
- محاسبه و به‌روزرسانی اتمیک موجودی حساب
- لیست تراکنش‌های هر حساب
- آرشیو حساب
- state با Riverpod
- UI واکنش‌گرا بر پایه Design System و Breakpoints موجود

## عمداً خارج از این فاز

اقساط، بدهی/طلب، اهداف مالی، صندوق اضطراری، گزارش‌ها و داشبورد تحلیلی در فازهای بعدی Finance پیاده می‌شوند.

## معماری

UI → Riverpod → FinanceRepository → NojinDatabase

جدول‌های موجود `finance_accounts` و `finance_transactions` در schema قبلی برای این فاز کافی بودند؛ migration جدید لازم نشد.

در ثبت تراکنش، درج تراکنش و تغییر موجودی حساب داخل یک transaction دیتابیس انجام می‌شود. حذف تراکنش نیز اثر آن را برعکس می‌کند.

## تست

تست Repository برای ساخت حساب، موجودی اولیه، درآمد/هزینه و rollback منطقی حذف تراکنش اضافه شد.

Flutter SDK در محیط اجرای این فاز در دسترس نیست؛ بنابراین اجرای واقعی flutter analyze و flutter test گزارش نشده و تست نهایی باید روی محیط محلی Windows/Chrome و Android انجام شود.
